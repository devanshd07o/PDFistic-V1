Privacy Policy & Data Protection Architecture

In short

PDFistic is a Windows desktop PDF reader and editor that runs entirely on your computer. The developer operates no servers, no telemetry endpoint, no analytics SDK and no database. Your documents, file names, file paths, reading history and identity are never transmitted to the developer, because there is no developer-side system capable of receiving them.

Two optional features can contact third parties, and only after you turn them on: Google Drive sync (limited to a hidden app-data folder in your own Drive) and the Bring-Your-Own-Key Zernexa AI Copilot (direct connections from your PC to the AI provider you choose). Voice input uses the Chromium Web Speech API and may involve Google speech services. Everything else is offline.

Local-first

Parsing, rendering, annotation and OCR execute on your CPU/GPU, inside your Windows session.

No middleman

No developer backend, proxy or relay exists. Optional cloud calls go straight from your PC to the provider.

Keys stay yours

OAuth tokens and API keys are encrypted with Windows DPAPI and never leave your machine in readable form.

Erasable

One in-app command or one folder deletion removes every local trace.

Architecture: Why There Is Nothing to Collect

PDFistic is an Electron application. It consists of a main process (Node.js) and sandboxed Chromium renderer processes. All document handling happens in those processes on your PC:

  • Parsing and rendering: Mozilla PDF.js decodes the PDF, rasterizes pages to canvas, extracts the text layer and renders fonts, inside an isolated in-memory renderer process. Page bitmaps and extracted text live in process memory and are released when you close the document or the application.
  • Annotation: Highlights, pen strokes and notes are held in memory while you work. The pdf-lib library writes them into the PDF binary only when you explicitly choose Save or Export, and only to the location you select on your own disk.
  • OCR: Optical character recognition uses Tesseract.js compiled to WebAssembly and bundled with the installer. It runs in an isolated Wasm memory heap on your hardware, with no network access required. No page image, bitmap crop or recognized text is sent to any computer-vision or OCR API.
  • No telemetry: The application contains no analytics SDK, crash-reporting SDK, advertising SDK, or tracking pixel, and makes no background "phone-home" request to the Developer.

What PDFistic Never Collects

The following categories are not collected, transmitted to the Developer, or stored by the Developer in any form:

  • Document contents, text excerpts, embedded or document metadata, and reading history.
  • File paths, directory structures and file names.
  • User identity, profile data, email address (other than one you send to the Developer voluntarily by writing to him), and hardware or device fingerprints.
  • In-app telemetry, clickstreams, usage counters and behavioral tracking.

This is a structural property of the software, not a settings toggle: there is no endpoint under the Developer's control for such data to be sent to.

Note that Microsoft may separately collect store-level acquisition and diagnostic information (for example, download counts and crash data) if you install through the Microsoft Store and have enabled those Windows settings. That collection is governed by the Microsoft Privacy Statement, and the Developer sees only aggregate reports Microsoft makes available through Partner Center.

Optional Feature: Google Drive Sync

Drive sync is disabled by default and activates only if you click the connect button and approve Google's consent screen.

5.1 How authorization works

  • Authorization uses OAuth 2.0 with PKCE (Proof Key for Code Exchange), the flow recommended for native desktop applications. No client secret is relied on to protect your tokens.
  • The only scope requested is https://www.googleapis.com/auth/drive.appdata. This grants access solely to PDFistic's private, hidden Application Data folder in your Google Drive. PDFistic cannot list, read, create or modify your personal files, photos or documents.
  • Access and refresh tokens are encrypted on your machine with Windows DPAPI and refreshed by contacting oauth2.googleapis.com directly. No developer-operated server participates in authorization or token refresh.

5.2 What is synced

Only your bookmarks, notes and reading progress are written to the hidden app-data folder, so they can be restored on another PC where you sign in. PDF files themselves are not uploaded. The data resides in your Google account, under your control, and is subject to Google's own privacy policy.

5.3 Google API Services User Data Policy disclosure

PDFistic's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

In operational terms:

  • Google user data is used only to provide the user-facing sync of bookmarks, notes and reading progress.
  • Google user data is never used to train, develop or fine-tune generalized artificial intelligence or machine learning models.
  • Google user data is never sold, leased, or transferred to third-party data brokers, advertisers or any other third party.
  • Google user data is not read by humans, including the Developer, because the Developer has no system that receives it.
  • Google user data is not used for advertising, including retargeting or interest-based advertising.

5.4 Revoking access

You can disconnect inside PDFistic (Settings), which deletes the locally stored tokens. You can also revoke access at any time at myaccount.google.com/permissions, and delete the app's hidden data from Google Drive settings under "Manage apps".

Optional Feature: Zernexa BYOK AI Copilot

Zernexa is PDFistic's docked and expandable AI study copilot. The Zernexa AI Copilot is strictly optional, privacy-isolated, and disabled by default until you enter your own API key for a supported model provider: Google Gemini API, Groq Cloud, Anthropic Claude, OpenAI, or OpenRouter. The Developer supplies no keys, no shared proxy quota, and no hosted cloud models.

6.1 Direct TLS 1.3 Data Flow

  • Zero Developer Proxy: When you submit a prompt to Zernexa, your prompt text and any active document excerpts or local RAG search context travel directly from your PC to the selected provider's official HTTPS endpoint over TLS 1.3. There is no intermediate developer proxy, telemetry relay, or server logging layer.
  • Intentional Transmission Only: Nothing is transmitted until you explicitly click send or press Enter. Transmitted text is strictly bounded to the specific question and cited document passages required to fulfill your inquiry.
  • Local STEM & Visual Rendering: When answering technical questions, Zernexa renders formulas and diagrams using client-side libraries bundled with the app (KaTeX for LaTeX math equations, Mermaid for flowcharts, ECharts for data plots, Leaflet for maps, and Pyodide for local Python sandbox execution). These execute entirely in-process on your PC with zero data leakage.
  • Zero Default Connectivity: If you never configure an API key, no AI-related network request is ever opened.

6.2 Hardware-Bound Key Vault (Windows DPAPI)

API keys for Zernexa are encrypted at rest using the Windows Data Protection API (DPAPI) via Electron's safeStorage.encryptString() and saved inside %APPDATA%\PDFistic\config.json. The ciphertext is bound to your specific Windows user login credentials and TPM hardware state, meaning it cannot be decrypted by another user account on the same machine or if the drive is accessed offline. Keys are decrypted into volatile memory strictly for the momentary duration of an API request.

6.3 Third-Party Provider Terms & Non-Training

Content transmitted to an external AI provider through Zernexa is governed by that provider's commercial terms and developer API privacy policies. Commercial API endpoints generally prohibit training generalized models on customer API payloads and enforce limited retention solely for security and abuse monitoring. Review their terms before submitting confidential material:

  • Google Gemini API: Gemini API Additional Terms of Service
  • Anthropic: Commercial Terms of Service
  • OpenAI: API Data Usage Policy
  • Groq and OpenRouter: The terms and privacy policies published on each provider's official portal.

You maintain full sovereign control over whether any document excerpt is transmitted to an external AI model provider, especially when handling legally privileged, regulated, or confidential records.

Optional Feature: Voice Input

Voice input uses the Chromium Web Speech API. Depending on the Chromium runtime configuration on your Windows system, audio may be transcribed locally or sent to Google Speech Services for transcription. PDFistic shows a notice before the microphone is activated, and the microphone is not accessed until you start voice input and Windows microphone permission allows it. The Developer never receives the audio or transcript. If you do not want audio processed by Google, do not use this feature, or disable microphone access for PDFistic in Windows Settings.

Diagnostic Logs

The main process writes operational events and error messages to %APPDATA%\PDFistic\logs\main.log. The log is local only and is never uploaded automatically. It is intended to contain technical events (startup, module errors, update status), not document contents. Error messages generated by underlying libraries can occasionally include a file name or path fragment, so review the file before attaching it to a public GitHub issue, and redact anything you do not want to share. You can delete the log at any time without affecting the application.

Permanent Data Erasure

Because all PDFistic data resides on your device, erasure is fully in your hands. Choose either method:

Method A: In-app wipe

  1. Open the wipe control

    In PDFistic, go to Settings → Privacy & Data.

  2. Click "Wipe All Data" and confirm

    This deletes preferences, encrypted API keys, encrypted OAuth tokens, logs and cached session state, and clears Chromium storage.

  3. Close the application

    Optionally revoke Google access at myaccount.google.com/permissions and delete any API keys from your AI provider dashboards, so the credentials are invalid at the source.

Method B: Manual deletion

  1. Quit PDFistic completely

    Close all windows and confirm no PDFistic process remains in Task Manager.

  2. Delete the data folder

    Press Win + R, enter %APPDATA%\PDFistic, and delete the folder in File Explorer (use Shift + Delete to bypass the Recycle Bin).

  3. Uninstall and revoke

    Remove the app from Settings → Apps, then revoke Google access and rotate or delete any AI provider API keys at the provider.

Erasure does not delete your own PDF files, copies synced to your Google Drive app-data folder (remove those through Google Drive settings), or content already processed by an AI provider (request deletion from that provider under its terms). Securely overwriting free disk space, if your threat model requires it, is an operating-system task outside PDFistic.

Security Controls

  • Process isolation: Document rendering runs in sandboxed Chromium renderer processes separate from the Node.js main process.
  • Credential encryption: Windows DPAPI through Electron safeStorage, bound to your Windows login.
  • Transport security: All optional cloud traffic uses HTTPS/TLS directly to the provider.
  • Least privilege: The Drive scope is limited to drive.appdata.
  • Third-party transparency: Core document rendering and OCR rely on battle-tested, permissively licensed open-source engines (PDF.js, Tesseract.js, pdf-lib) running in local sandboxes. Report any vulnerabilities privately by email (Section 18).

No software is free of defects, and DPAPI protects against other users and offline disk access but not against malware running under your own logged-in account. Keep Windows updated and use standard endpoint protection.

Children's Privacy (COPPA)

PDFistic is a general-purpose utility and is not directed to children under 13. The software does not knowingly collect personal information from children under 13. Because the application collects no personal information at all, there is no child data to disclose or delete on the Developer's side. Parents or guardians who believe a child has submitted information to the Developer by email can write to the address in Section 18 and it will be deleted. Parents are responsible for supervising a child's use of optional third-party features such as AI providers and Google accounts, which carry their own age requirements.
